# Fullpad

Editor de notas e markdown rápido, estilo Notepad++: nada se perde ao fechar. Markdown renderizado e editável (live preview). Rust + Tauri 2 + CodeMirror 6.

O roteiro de entrega por fases está em [PLANO.md](PLANO.md). Siga-o: cada fase termina numa PARADA em que o usuário valida antes de seguir.

Ideias futuras, melhorias e bugs ficam nas **issues** do GitHub, não em arquivos do projeto: padrão em [rules/issues.md](rules/issues.md), ranking na issue fixada #35. Ao entregar uma, a `gerar-versao` a fecha com o milestone da versão.

- A UI conversa com o Rust só por comandos IPC (`ui/src/api.ts` ↔ `crates/app/src/main.rs`). Lógica de dados vive em `crates/core`, não em `app`.
- Menu superior do tipo de arquivo (`langMenuItems` em `menus.ts`): o botão ao lado de "Linguagem" muda de nome com a aba ativa (`mountMenuBar` devolve `refresh`, chamado em `refreshStatus`): JSON (formatar, indentação, árvore), CSV (separador, cabeçalho, decimal), Markdown (exportar HTML/PDF, copiar como HTML, visão), DBML e Mermaid (visão do diagrama) e Texto (quebra de linha, localizar, substituir, ir para linha).
- Visão do arquivo (`mode` da aba): `source` (só código), `rendered` (markdown renderizado no próprio texto; no DBML, diagrama ao lado) ou `split` (código e renderizado lado a lado; Ctrl+Shift+E). Menu Visualizar e botão "Visão" da barra de status.
- Janelas: cada aba pertence a uma janela (`TabState.window`; `main` é a principal e encerrar o app). Todas as janelas rodam a mesma UI e só enxergam as próprias abas (`load_startup` devolve `Session::view_for`). `session.json` é único: `save_window` só **atualiza e reordena** as abas da janela (nunca remove: uma aba pode estar chegando de outra janela); fechar é `close_note`, mover é `move_tab`/`drop_tab`, que gravam a aba na janela de destino e avisam por evento `tab-incoming`. Ao mover, o texto pendente é gravado antes e o histórico de desfazer fica para trás. Fechar uma janela flutuante devolve as abas à principal; fechar a principal grava tudo (`app-exit`) e encerra. Janelas flutuantes são reabertas na posição salva e não têm o menu superior (só abas e barra de status).
- Grade de painéis: uma janela tem vários **painéis** (grupos de abas, como no VS Code), lado a lado ou empilhados. Cada aba tem `TabState.group`; a árvore de divisões (`grid.ts`: `leaf`/`split` com pesos) fica em `WindowState.layout` na sessão, opaca para o Rust, e a UI a valida ao ler (`normalize`: nunca confia no que veio do disco). Cada painel tem editor, barra de abas, markdown renderizado e diagrama próprios (`Group` em `main.ts`); só o painel com o foco (`cur`) recebe menus, atalhos e barra de status, e `session.active` é sempre a aba aberta nele. Clicar ou focar dentro de um painel o torna o atual (`enterGroup`, que **não** redesenha as barras: senão a aba clicada sumiria no meio do clique). Dividir: Ctrl+\ (direita), Ctrl+Shift+\ (abaixo), menu da aba; com várias abas, a aberta vai para o painel novo, com uma só nasce uma nota vazia. Arrastar uma aba (`tabdrag.ts` avisa o ponto local `cx`/`cy`) mostra **alvos visíveis** em todos os painéis (`dock.ts`, camada `.dock-layer`, retângulos translúcidos que acendem sob o ponteiro, com o realce da área resultante por cima): um retângulo no meio de cada borda divide só aquele painel; barras finas tracejadas na borda externa de cada bloco (pilha de painéis, `wrapCandidates`) dividem o bloco inteiro (a mais de fora é o maior bloco); um retângulo no centro de **outro** painel move a aba para ele (código e preview são uma unidade: trocam juntos). Os cantos ficam livres. Fora dos alvos: sobre uma barra de abas, entra na lista na posição exata; no resto de outro painel, também move para ele; no meio do próprio painel, sobre o preview não faz nada e sobre o código segue como antes (janela nova). Uma aba sozinha não divide o próprio painel (mas pode dividir o bloco dele). Cada divisa tem três pontinhos (`.splitter-grip`): clicar abre o menu (o botão direito na divisa também), mas segurar e arrastar, de qualquer ponto da divisa, redimensiona; inverter os lados (`swapAdjacent`), trocar entre lado a lado e empilhado, dividir igualmente. Aba arrastada de **outra janela** (`drag_move` acha a janela sob o ponteiro, não só a barra; `drag-over` leva `cx`/`cy`): vê os mesmos alvos, menos o do centro: entra pela barra de um painel (posição exata) ou por um alvo de borda/bloco (abre um painel novo ali, e a aba é a última da lista); o resto do painel não aceita, e a aba vira uma janela própria como sempre. Quem decide é a janela de destino, que avisa o Rust com `drag_accept`; `drop_tab` só entrega a aba se houve aceite, e o lugar mostrado fica em `incoming` até a aba chegar (o `drag-leave` já limpou a marca na tela). Painel que fica sem abas some e os vizinhos ocupam o espaço. A janela reserva e a gravação (`save_window` leva `layout`) funcionam como antes.
- Arrastar uma aba para fora da barra (`tabdrag.ts` + `drag_start`/`drag_move`/`drop_tab`): enquanto arrasta, só uma **sombra** (janela `ghost`, minúscula, transparente e que o mouse atravessa) acompanha o ponteiro com o nome da aba; a aba original fica no lugar, apagada, e nada muda na sessão até soltar. Ao soltar, `drop_tab` leva a aba para a barra de outra janela que estiver sob o ponteiro (que mostrou um espaço no lugar exato da inserção por `drag-over`/`drag-leave`) ou a uma janela nova na posição do ponteiro. Exceção: se a aba é a **única** de uma janela flutuante, é a própria janela que anda com o mouse (sem sombra); sobre a barra de outra janela ela fica logo abaixo do ponteiro, para não cobrir o espaço da inserção, e solta por aí ela só fica onde está. Para a janela nova aparecer na hora, o Rust mantém uma reserva escondida e já carregada (`prewarm`, label `spare-*`), que espera a aba em silêncio e só aparece ao recebê-la (`window_ready`). Eventos endereçados a uma janela (`emit_to`) são ouvidos com `listenHere` (`events.ts`): o `listen` global recebe também os das outras janelas, e a aba chegava em todas. Toda janela escuta `tab-incoming` **antes** de ler a sessão (`incomingReady`), senão uma aba que chegasse nesse intervalo se perderia.
- Visão em janela separada: `TabState.detached` (menu Visualizar > "... em janela separada"). A aba continua uma só, na janela dona; a janela `preview-<aba>` recebe o texto por eventos (`pv-text`, `pv-cursor`) e devolve `pv-hover:<aba>` (destaque da linha no código), `pv-ready:<aba>` e `pv-closed:<aba>` (fechar a janela traz a visão de volta ao lado do código). Mover a aba de janela ou escolher outra visão a recoloca ao lado do código.
- Abas em lote e fixadas (`ui/src/tabsets.ts`, funções puras testadas em `tabsets.test.ts`; menu de contexto da aba): **Fixar/Desafixar** (fixar também seleciona a aba; `TabState.pinned`, omitido no `session.json` quando falso) troca o × por um alfinete sempre visível (clicar nele desafixa), junta as fixadas à esquerda do painel e as protege de Ctrl+W, botão do meio e de todo fechamento em lote. **Fechar outras / Fechar todas / Fechar salvos** valem só para as abas da janela (a sessão da UI já só enxerga as dela), todos os painéis, e pulam as fixadas; "salvos" são as abas ligadas a arquivo sem alterações pendentes (notas soltas ficam, o texto delas só existe no Fullpad). Se algum alvo tem alterações em arquivo, `closeMany` pergunta uma vez (Salvar/Não salvar/Cancelar; Cancelar ou falha ao salvar não fecha nada). **Salvar todos** (Arquivo, menu da aba, Ctrl+Alt+S) grava as abas de arquivo com alterações. O botão do meio fecha pelo `mouseup` (o `mousedown` é cancelado para o WebView não ligar a rolagem automática) e a roda comum sobre a barra de abas rola na horizontal.
- Reabrir aba fechada (Ctrl+Shift+T reabre a última; Arquivo > "Histórico de abas fechadas…" ou Ctrl+Shift+H abre uma janelinha com filtro e as mais antigas, `history.ts`): `close_note` guarda o estado da aba em `trash/<id>.json` ao lado do texto (`Store::close_tab`); `list_closed` lista as mais recentes e `restore_tab` devolve a nota à janela que pediu, com título, arquivo, linguagem e visão de antes.
- JSON (`Language::Json`, `.json`/`.jsonc`/`.geojson`/`.webmanifest` ou menu Linguagem; sem detecção por conteúdo): a árvore fica sempre ao lado do código, como o diagrama do DBML (Ctrl+E, "Árvore em janela separada"). Toda a lógica é do Rust (`crates/core/src/json.rs`): parser **próprio** iterativo (não `serde_json::Value`: precisa das posições, do texto original dos números e das chaves repetidas), com posições em **UTF-16** (as do CodeMirror; bytes desalinhariam com acento e emoji), erros com linha/coluna, formatação que reemite o texto original dos escalares (`12345678901234567890`, `1.0` e `1e400` não mudam) e recusa quando há comentários (apagá-los seria perder texto). A análise é tolerante (comentários e vírgula sobrando) para `.jsonc` e `tsconfig.json`. A UI chama `json_analyze` (nós em pré-ordem: `end` é o índice depois do último descendente), `json_check` (só valida, para sublinhar o erro mesmo sem a árvore), `json_format` (indentação `2`/`4`/`tab`/`min`, ordenar chaves). Acima de `MAX_NODES` (300 mil) a árvore não é montada; acima de 8 milhões de caracteres a visão desliga (o editor continua normal). Dicas de valor (`hint`) decididas no Rust: `url`, `mail`, `image` (URL com extensão de imagem), `image-data`, `image-local` e `color` (só `#hex`, `rgb()`, `hsl()`: nomes como `red` não, para não acender palavras comuns). Link abre pelo navegador do sistema (`open_url`, só `http`/`https`/`mailto`); imagem remota só carrega ao passar o mouse e só com extensão de imagem; imagem local passa por `json_preview_image` (só extensões de imagem, até 8 MB, relativa à pasta do arquivo da aba), nunca por protocolo de arquivos aberto. Menu superior "JSON" (Formatar `Alt+Shift+F`, seleção, minificar, ordenar chaves, indentação, expandir/recolher, copiar caminho) e botão direito (no código e em cada nó da árvore); formatar é uma só transação do CodeMirror (um passo no Ctrl+Z) e mantém o cursor pelos caracteres que não são espaço (`mapCursor`). Ligação código ↔ árvore como a do DBML: o mouse num nó pinta o trecho no código (`hintLines`) e o cursor do editor abre e destaca o nó (`nodeAt`), valendo só se a árvore é da mesma versão do texto (`rev`); o caminho do nó (`$.lista[0].nome`) aparece na barra de status.
- YAML e TOML (`Language::Yaml`/`Toml`, `.yaml`/`.yml`/`.toml` ou menu Linguagem; sem detecção por conteúdo): a mesma árvore ao lado do código do JSON (mesmo painel `json/panel.ts`, que ganhou `setFormat`; Ctrl+E), com validação (erro sublinhado, `data_check`) e dicas de valor decididas no Rust. TOML: `toml_edit` (posições de chaves e valores no texto original; números como escritos; datas aparecem como texto). YAML: `saphyr-parser` (eventos com posição) e tipos pelo esquema core do YAML 1.2; vários documentos (`---`) viram uma lista na raiz, apelidos (`*a`) **não são expandidos** (aparecem como `*a`) e `<<` é uma chave comum. Posições em UTF-16 (`structured::Utf16`). **Não há formatação** (reescrever perderia comentários, âncoras e estilos) nem árvore em janela separada; o menu "YAML"/"TOML" tem visão, expandir/recolher e copiar caminho. Pendências: formatar sem perder comentários, conversão entre JSON/YAML/TOML.
- Abas de leitura (PDF e EPUB, Fase 10 do [PLANO](PLANO.md)): `TabState.kind` (`text` | `pdf` | `epub` | `unknown`; ausente nas abas de texto) e `TabState.reader` (posição de leitura `{page, frac, zoom}`, opaca para o Rust e validada pela UI em `reader/pos.ts`). O arquivo é do usuário e **nunca é gravado**: `Store::save_file` recusa aba de leitura, `save()` da UI sai logo, e `apply_window` não deixa a UI mudar o `kind` de uma aba. Um `kind` que esta versão não conhece vira `unknown` (só leitura, sem conteúdo), nunca `text`. A aba segue o caminho das outras (sessão, lixeira, mover entre janelas): `open_reader` cria uma nota vazia em `notes/` só como marcador, não lê o arquivo, e já registra a aba na sessão. **Abrir não carrega**: o painel mostra o nome, o tamanho (só metadados) e o botão "Carregar"; só então o pdf.js é importado e os bytes são pedidos por `reader_read` (binário cru por `tauri::ipc::Response`, faixas de até 16 MB, em pedaços de 1 MB; sempre pelo id da aba, nunca por caminho vindo da UI). **Antes** de o pdf.js tocar no arquivo, `reader_check` (`scan_pdf`, no Rust) desinfla cada stream `/FlateDecode` só contando bytes, com teto: um trecho que passa de 32 MB descomprimidos expandindo mais de 200 vezes (ou de 256 MB) é bomba de compressão (o pdf.js não tem limite e um arquivo de 1 MB chegou a pedir 2,3 GB). A aba então não carrega: mostra o aviso e só o botão "Carregar mesmo assim" segue adiante; a verificação passa de 15 s sem concluir e o arquivo passa. **EPUB** (`.epub`, lido por `core::epub`, não pelo epub.js): `epub_open` devolve título, autora, capítulos e sumário (nav do EPUB 3 ou NCX do EPUB 2; sem nenhum, capítulos numerados) e `epub_chapter` o capítulo já limpo; o `Epub` aberto fica em `AppState.epubs` (só metadados) e os capítulos são lidos do ZIP sob demanda. **O ZIP nunca é extraído**: só se procura a entrada pelo nome, com o caminho normalizado (nada de `..` que saia da raiz, esquema ou caminho de disco), com teto de bytes por leitura (conta o que foi de fato descomprimido), teto de 20 mil entradas e DRM recusado. O XML (`quick-xml`) não resolve entidades nem DTD ("billion laughs" e entidade externa viram texto). O XHTML passa pelo `ammonia` (lista de permissão; sem scripts, eventos, iframe, form, svg, base, meta, link): imagens viram `data:` lidas do próprio livro (8 MB cada, 24 MB por capítulo) e links só `http`/`https`/`mailto` ou `epub:<capítulo>#fragmento`. O CSS do livro passa por `css::sanitize` (lista de permissão: só propriedades de texto e caixa; sem `url()`, `position`, `content`, `@import`, `@font-face`, escapes nem `!important`) e vai numa `@layer book` abaixo da `@layer app` do tema do Fullpad; no tema escuro as cores do livro são trocadas pelas do tema. O capítulo aparece num `<iframe sandbox="allow-same-origin">` (nunca `allow-scripts`) com CSP `default-src 'none'; img-src data:`: nenhum script do livro roda e não há rede; o mesmo domínio serve só para o app escutar cliques, rolagem e teclas lá dentro (teclas são repassadas à janela, Ctrl+roda dá zoom do texto). O zoom do EPUB é o tamanho do texto (60% a 300%). A posição de leitura usa os mesmos campos do PDF (`page` é o capítulo, `frac` a rolagem dentro dele) e a posição por arquivo vale igual. **Busca no documento** (Ctrl+F com um PDF/EPUB carregado, menu "PDF"/"EPUB" ou Editar > Localizar): barra acima do documento com o campo (busca 350 ms depois de parar de digitar, ou Enter), "3 de 17", ▲/▼ (Shift+Enter volta), Esc fecha. Ignora maiúsculas e acentos (`find.ts`, `fold` com o mesmo comprimento do original) e varre as unidades em ordem, mostrando o primeiro resultado na hora e parando em 500; consulta de 2 a 100 letras. O texto vem do leitor: no PDF, o `getTextContent` de cada página (`pdfview.find.textOf`); no EPUB, `epub_text` (`Epub::chapter_text`: texto puro, sem marcação, com quebra entre blocos; não lê imagens nem CSS). O realce usa a API `CSS.highlights` (`::highlight(fp-find)` e `fp-find-current`), sem mexer no documento, então seleção e citação seguem iguais; no PDF vale para as páginas desenhadas (a camada de texto), no EPUB dentro do iframe, e ao trocar de capítulo o novo já vem realçado. O resultado em foco é a n-ésima ocorrência da unidade, localizada de novo no texto da tela. **Citação**: selecionar um trecho no documento e usar "Copiar como citação" (botão direito sobre o documento, menu "PDF" ou Ctrl+Shift+C com o foco no leitor) copia um bloco markdown com a origem (`> trecho` e `> — *Título*, p. 42`; `pp. 42–43` se atravessa páginas) e mostra "Citação copiada". No EPUB vale o mesmo (menu "EPUB", botão direito e Ctrl+Shift+C de dentro do livro): a seleção vem do documento do iframe (`ReaderView.selection`, com os parágrafos preservados por `fragmentToText`) e a origem é o título do livro e o capítulo (`> — *Dom Casmurro*, cap. 3 (Nome do capítulo)`; sem nome de capítulo, só `cap. 3`). As quebras de linha do PDF viram espaço, a hifenização de fim de linha é desfeita e uma linha em branco separa parágrafos; só escreve na área de transferência. **Posição de leitura por arquivo**: além de `TabState.reader` (por aba), o app lembra a última posição de cada arquivo em `reader-positions.json` na pasta de dados (`Store::remember_reader_position`, escrita atômica, as 2000 mais recentes, arquivo ilegível vai para `.corrupt` e recomeça vazio). A chave é a **identidade do conteúdo** (`reader::fingerprint`: tamanho + FNV-1a do começo e do fim, 128 KB lidos), não o caminho: mover ou renomear o arquivo mantém a posição; editá-lo a perde. Só é calculada ao carregar (`reader_memo`, que também devolve a posição lembrada); a da sessão vale mais que a lembrada. O painel grava 1,5 s depois de parar de rolar e na hora ao trocar de aba ou fechar (`reader_remember`, que só aceita chaves nesse formato). Depois de carregada, a aba recarrega sozinha ao voltar a ela nesta execução; após reiniciar o app volta ao botão. Arquivo ausente: o aviso troca o botão por "Localizar arquivo…" (`reader_relocate`, mesmo tipo). Arquivo alterado com a aba carregada: ao focar a janela aparece uma faixa "Recarregar" (nunca recarrega sozinho). O pdf.js roda sem o visualizador completo, então o JavaScript do PDF não executa; links só `http`/`https`/`mailto` pelo `open_url`; imagens acima de 16 Mpx e canvas acima de 64 MB são ignorados; página ou abertura que passa de 12 s/20 s é abandonada (o worker é encerrado), uma segunda rede para o que a verificação não pega. Fontes, cmaps e wasm do pdf.js são copiados para `ui/public/pdfjs/` pelo `vite.config.ts` (ignorado pelo git) e viajam no app. Em `main.ts` a aba de leitura é `isReader(tab)` e `effectiveLang` devolve `"pdf"` (menu "PDF" com Carregar/Localizar, barra de status com a página); o editor fica escondido (`.body.reading`), o painel é `Group.reader`.
- CSV (`Language::Csv`, `.csv`/`.tsv` ou menu Linguagem; sem detecção por conteúdo da *linguagem*): o separador sim é detectado, pela estrutura (`csv::detect`, comando `csv_detect`: cabeçalho e primeiras linhas, fora das aspas; `.tsv` é tab). `TabState.csv` guarda as escolhas do usuário (`{delimiter, header, decimal}`, opaco para o Rust, validado por `csv/settings.ts`): `delimiter: "auto"` redetecta ao abrir e ao editar; qualquer outro valor é escolha manual, **nunca é redetectado** e sobrevive a reiniciar. O decimal é ponto por padrão (sem inferência; vírgula só se o usuário escolher). Menu superior "CSV" (separador, cabeçalho, decimal). Colunas coloridas no código (`csv/lang.ts`). **Tabela** (Fase 11.C e 11.D): três visões, como o markdown, mas a padrão é **só a tabela** (`mode: rendered`; o editor fica escondido, vivo, com o texto e o histórico, `.body.tableonly`), `source` (só código) e `split` (tabela e código lado a lado; Ctrl+E alterna tabela/código, Ctrl+Shift+E o lado a lado). O texto da aba vai ao Rust uma vez (`csv_load`, que indexa em `AppState.csvs`, por aba) e a tabela pede só as linhas da tela (`csv_rows`, até 500 por chamada); depois de editar o código, recarrega 300 ms depois de parar de digitar (reindexa o texto inteiro: é o ponto a otimizar se ficar lento em arquivos muito grandes). Ordenar (clique esquerdo no cabeçalho alterna crescente, decrescente, sem ordem; o botão direito só abre o menu, com Ordenar > Crescente/Decrescente/Limpar ordenação, filtrar por essa coluna e copiar o nome) e filtrar (caixa acima, por coluna ou em todas, sem maiúscula nem acento) são só uma lista de índices de linha (`csv::Csv::view`, `csv_view`) e nunca mexem no texto; coluna só de números ordena como número (no decimal escolhido), senão como texto sem acento (datas `dd/mm/aaaa` ordenam como texto), vazias vão sempre para o fim. Rodapé: uma célula selecionada mostra a coluna inteira da visão, uma faixa mostra a seleção (soma, média, mínimo, máximo, contagem; o que não é número no formato escolhido fica de fora e é contado). Ligação código ↔ tabela como no JSON: o cursor do código destaca a célula (`csv_locate`) e clicar numa célula leva o cursor ao trecho (`csv_cell`), só se a tabela for da mesma versão do texto (`rev`). Os dois sentidos também valem para o fundo: as células selecionadas na tabela (até 2 mil linhas) pintam o texto delas no código (`.cm-csv-sel`) e a célula sob o mouse pinta o dela, mais suave (`.cm-csv-hover`); são marcas do CodeMirror (`csvSelectionMarks`/`csvHoverMarks` em `editor.ts`), apagadas por qualquer edição. Clicar no vazio da tabela ou Esc tira a seleção. A altura é **por linha** (arrastar a borda de baixo do número da linha; duplo clique volta a 24 px; de 20 a 400 px; só as linhas mudadas ficam guardadas, pela posição na tela, lembradas por aba e fora da sessão; mudar ordem, filtro ou a quantidade de linhas as zera porque as posições deixam de valer); a partir de 44 px o texto das células daquela linha quebra em linhas em vez de ser cortado. **Edição** (11.D): duplo clique, F2 ou Enter numa célula abre um campo (`textarea`, Shift+Enter quebra linha); digitar numa célula selecionada começa a edição trocando o conteúdo; Enter grava e desce, Tab grava e anda para o lado, Esc descarta, clicar fora grava. Delete/Backspace esvazia a seleção (até 5 mil linhas). A tabela **nunca grava por conta própria**: `csv_edit` (`Csv::edit_cells`) só devolve as trocas de texto (UTF-16, do texto que foi indexado) e a UI as aplica no editor numa transação só (`onEdit`, um passo no desfazer, Ctrl+Z/Ctrl+Y da tabela usam o histórico do editor), só se o texto ainda for o indexado (`rev`); depois refaz o índice na hora. Só as células editadas mudam (o resto do arquivo, incluindo `\r\n`, fica igual) e uma célula só ganha aspas se o valor tiver separador, aspa ou quebra de linha (as que já tinham aspas as mantêm); apagar uma célula que a linha não tem não cria separadores. Enquanto a tabela se atualiza depois de uma edição no código, editar na tabela fica bloqueado ("A tabela está atualizando"). Com ordem ou filtro ligados, a seleção segue a posição na tela, então editar a coluna ordenada pode reposicioná-la. **Estrutura** (11.E, `csv_structure`, `Csv::insert_rows/delete_rows/insert_col/delete_cols/move_col/sort_file`): também só devolve trocas de texto (mesma transação, mesmo `rev`). Botão direito numa célula: inserir linha acima/abaixo e apagar as linhas selecionadas (as posições são as da tela; o Rust as traduz pela visão). Botão direito no cabeçalho: inserir coluna à esquerda/direita, apagar, mover para um lado, inserir linha no fim e "Ordenar o arquivo por esta coluna" (a única ação que reescreve a ordem das linhas no texto; o cabeçalho fica, e os terminadores passam a ser o da primeira linha). Colunas e linhas inteiras são refeitas pelos campos **crus** (aspas das células que ficam não mudam); linhas em branco e linhas curtas demais para a posição ficam como estão. Mexer em colunas limpa a ordem e o filtro por coluna da tabela. **Colar** (Ctrl+V ou "Colar" no botão direito): o texto da área de transferência vira uma grade (tab entre colunas, quebra entre linhas, campos entre aspas como no Excel e no Copiar da tabela) e é gravado a partir do canto de cima à esquerda da seleção, em qualquer formato; passando do fim cria linhas (`edit_cells` aceita linhas além da última, até 20 mil) e colunas. Uma célula só com várias selecionadas preenche todas. Copiar e colar uma linha: clicar no número da linha seleciona ela inteira. **Renomear coluna** (botão direito no cabeçalho, só com "primeira linha é o cabeçalho"): edita a célula do cabeçalho sobre ele. Tab numa célula selecionada com "…" abre o popover (Copiar em destaque): Enter copia e fecha, Tab de novo fecha sem copiar. Teto de 50 milhões de caracteres para ligar a tabela; acima disso uma faixa fina abaixo das abas (`Group.noteEl`, largura total) avisa que só o código está disponível. A coluna do número da linha cabe o maior número (`--csv-num-w`) e a borda direita do canto do cabeçalho a redimensiona (duplo clique volta ao automático; por aba, fora da sessão). Ctrl+C e o botão direito numa célula copiam a seleção como TSV (com os textos inteiros, mesmo os que a tabela recebe cortados). Texto que não cabe na célula ganha um "…" clicável (`.csv-more`, medido depois de desenhar, porque o cortado nativo do navegador não é clicável) que abre um popover com o texto completo e o botão Copiar; ele fecha ao tirar o mouse da célula e dele, ou com Esc. O separador do CSV é detectado a partir de `syncCsvTable` (e não só de `show()`): o `boot()` não passa por `show()`, então sem isso a tabela nunca ligava ao reabrir o app.
- Números de linha: margem do CodeMirror (`lineNumbers()` no compartimento `gutterC` de `editor.ts`, `TabConfig.lineNumbers`), separada do texto (fundo e borda próprios, não selecionável, não faz parte do documento). Valem para qualquer tipo de arquivo, só onde o código aparece (visões código e lado a lado; somem no markdown renderizado e na tabela do CSV). Menu Visualizar (e o fim do menu de texto) > "Números de linha"; ligado por padrão, lembrado em `localStorage` `fullpad.lineNumbers`, para todas as abas.
- Preview do markdown: **nunca use margem vertical** (`margin-top/bottom`) em linhas ou widgets do `.cm-md-*`: o CodeMirror não a conta no mapa de alturas e o clique cai na linha errada. Use `padding` (há teste em `preview-css.test.ts`).
- O documento é sempre texto puro; renderizar markdown ou DBML nunca reescreve o conteúdo.
- DBML: o painel, o diagnóstico (e o autocomplete) compartilham um único `Compiler` em `ui/src/dbml/service.ts`; `ui/src/dbml/editor.ts` entrega os recursos de editor por `import()` dinâmico. `.dbml`/`.dbmlx` ou escolha manual no menu Linguagem (sem detecção por conteúdo). O diagrama usa `@dbml/parse` **v11** (entende a sintaxe nova: relações opcionais `?>`/`<?`, `Records`; o `@dbml/core` pesa 15 MB e a 3.9 não conhece a sintaxe nova) com um `MemoryProjectLayout` de um arquivo só e `@dagrejs/dagre`, ambos via `import()` dinâmico em `ui/src/dbml/panel.ts`: **nada de `dbml/` pode ser importado estaticamente a partir de `main.ts`**, para não pesar a abertura do app. Só visualização por enquanto (sem posições salvas). O modelo guarda o trecho do texto de cada elemento (`span`): passar o mouse no diagrama pinta a linha no código (`hintLines` em `editor.ts`, sem selecionar) e o cursor do editor destaca o elemento no diagrama (`Rendered.focusAt`). Os dois só valem se o diagrama for da mesma versão do texto (`docRev`), senão os trechos apontariam para o lugar errado.
- Atualização automática (`tauri-plugin-updater`): a principal procura versão nova ao abrir e pelo menu Ajuda; antes de instalar, `saveEverything` faz todas as janelas gravarem (o instalador fecha o app). Publicar uma versão: [rules/build-windows.md](rules/build-windows.md).
- Nota de versão: o texto de `crates/app/release-notes.md` vai embutido no app. Na primeira abertura de uma versão nova (`Store::note_running_version`, arquivo `version` na pasta de dados; sem ele, conta como atualização se já havia sessão), a principal abre a nota "Nota de versão V<versão>" (`startup_release_notes`); Ajuda > "Ver nota de versão" abre de novo (`release_notes`), ou ativa a que já estiver aberta. São abas com `TabState.release_notes`: **somente leitura** (`readOnly` no editor, compartimento `readOnlyC`: seleciona e copia, mas não digita, cola, recorta, substitui nem formata; a barra de formatação e a caixa de tarefa não agem; a busca global não as troca) e **sem Salvar nem Salvar como** (`save()` recusa e os itens do menu ficam desabilitados, pois o texto é do app); fechar apaga o texto de vez, sem ir para o histórico de abas fechadas (só elas).
- Histórico de versões (`crates/app/CHANGELOG.md`, embutido no app como o `release-notes.md`; `crates/core/src/changelog.rs`, funções puras testadas): um cabeçalho `## 2.0.0 · 2026-11-04` por versão, da mais nova para a mais antiga, com as seções em `###` (um `##` que não é versão, ou dentro de bloco de código, é texto). A skill `gerar-versao` acrescenta a versão nova no topo a cada release; as versões até a 2.0.0 foram reconstruídas das mensagens das tags. Ajuda > "Histórico de versões" (`open_changelog`) abre **o changelog completo** numa aba só de leitura (`release_notes`, como a nota de versão; abrir de novo ativa a que já existe). Sem diálogo nem intervalo: para achar uma versão, use o sumário lateral (as versões e suas seções) ou a busca. Ctrl+F e a busca global valem na aba. **Depois de atualizar pulando versões**, `startup_release_notes` mostra tudo o que entrou desde a versão que a pessoa tinha (`Store::previous_version`, lida antes de `note_running_version` trocar o arquivo `version`); com uma só versão nova, é o `release-notes.md` de sempre. Ficou fora: resumo entre a instalada e a nova no diálogo de atualização.
- Dados em `%APPDATA%\fullpad` / `~/.local/share/fullpad`. `FULLPAD_DATA_DIR=/caminho` sobrescreve (use para testar sem mexer nas notas reais).

## Rodar e testar

Pré-requisitos: Rust, Node, pnpm. Dependências de sistema do Linux estão no `README.md`.

```sh
pnpm --dir ui install
cargo test -p fullpad-core            # testes do core (na raiz)
pnpm --dir ui exec vitest run         # testes da UI
pnpm --dir ui build                   # tsc --noEmit + vite build
cd crates/app && cargo tauri dev      # app em desenvolvimento
cd crates/app && cargo tauri build    # instalador / binário
```

Não há pipeline de CI por enquanto (nenhum workflow do GitHub); testes e build rodam localmente. Neste WSL só `core` e a UI compilam nativamente (faltam libs do webkit para `app`); o `app` para Windows sai por cross-compile ([rules/build-windows.md](rules/build-windows.md)). Veja "Pendências de ambiente" no PLANO.

## Convenções

- Código e identificadores seguem o que já existe no módulo; texto de UI, docs e commits em português.
- Mudou comportamento, arquitetura, comando ou convenção: atualize `docs/` no mesmo commit (veja [rules/harness.md](rules/harness.md)).
- Commits: [rules/commits.md](rules/commits.md).
- Persistência (`crates/core`): [rules/persistencia.md](rules/persistencia.md).
- Arquivos de exemplo (`examples/`): [rules/exemplos.md](rules/exemplos.md).
- Publicar uma versão (tag, notas, instalador, release): skill [gerar-versao](skills/gerar-versao/SKILL.md).
- Bugs, melhorias e novidades: issues do GitHub, no padrão de [rules/issues.md](rules/issues.md); skills [criar-issue](skills/criar-issue/SKILL.md) (`--bug`, `--improvement`, `--feature`, `--draft`, `--milestone=`), [editar-issue](skills/editar-issue/SKILL.md) (`--milestone=`, `--label=+x,-y`, `--priority=`, `--refinar`) e [implementar-issue](skills/implementar-issue/SKILL.md) (`--approve`, `--commit`; os commits levam `Refs #n` e a `gerar-versao` fecha a issue).
- Ao terminar qualquer ajuste, gere o build de Windows e reporte o resultado: [rules/build-windows.md](rules/build-windows.md).

## Segurança

- Sem segredos no repositório. Caminhos de arquivo vindos da UI são tratados como entrada do usuário: o app só lê/grava o que o usuário abriu ou salvou explicitamente.
- Nunca sobrescreva arquivo do usuário sem escrita atômica (veja a regra de persistência).
